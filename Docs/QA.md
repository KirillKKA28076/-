# Проверка версии 0.2

## Честный статус

В среде подготовки коммитов нет Unity Editor и лицензированного Unity batch runner. Поэтому Unity compilation, EditMode, PlayMode, визуальная проверка и Windows build должны быть выполнены локально.

`Tools/validate_project.py` и GitHub Actions проверяют структуру, грамматику C#, JSON, `.meta`/GUID, обязательные пути и пакеты, ссылку сцены и кириллический шрифт. Они не проверяют Unity API и игровое поведение.

## Подготовка

1. Открыть корень проекта в Unity **2022.3.62f1**.
2. Дождаться разрешения пакетов и завершения импорта.
3. Запустить **Тёплый хлеб → 1. Подготовить проект**.
4. Запустить **Тёплый хлеб → 4. Проверить проект**.
5. Убедиться, что Console не содержит красных ошибок.
6. Открыть `Assets/WarmBread/Scenes/Bakery_Street.unity`.

## Smoke test в PlayMode

1. Нажать Play. Мир должен появиться без розовых материалов; русский текст должен читаться.
2. Нажать «Открыть ларёк». Проверить WASD, мышь, E/ЛКМ, F, X, Tab, R и Esc.
3. Убедиться, что игрок не проходит через стены, полки и прилавок.
4. Проверить, что луч взаимодействия работает через триггер окна и на объектах с дочерними коллайдерами.
5. Проверить горячие клавиши 1–4 после добавления пользовательского товара: они должны по-прежнему выбирать базовые ID.

## Покупатели и очередь

1. Первый покупатель появляется и доходит до окна.
2. Заказ содержит 1–3 реально имеющихся товара.
3. Школьник не заказывает товары с ID `sig_*`.
4. Пользовательский массив из одного покупателя не вызывает исключение.
5. Поздний посетитель определяется флагом `LateVisitor`, а не последним индексом.
6. Во время кассы терпение текущего покупателя не уменьшается.
7. Без обслуживания покупатель уходит примерно через 120 секунд, пакет возвращается, репутация уменьшается.
8. Следующий клиент корректно продвигается.
9. После успокоения конфликта новый конфликт не возникает в следующем кадре.

## Заказ, касса и склад

1. Лишний товар блокирует выдачу.
2. X возвращает пакет с неизменным `bakedAt`.
3. Неверная сдача не меняет кассу и оставляет транзакцию открытой.
4. Произвольный номинал, отсутствующий в `Money.Denominations`, не принимается.
5. Верная сдача добавляет ровно стоимость заказа один раз.
6. Повторный клик после завершения не дублирует продажу.
7. FIFO выдаёт самую старую партию.
8. Пирожки портятся после шести игровых часов; вода и лимонад не портятся.
9. Неизвестный товар не меняет привязку горячих клавиш.

## Поставки и завершение дня

1. Заказать ящик: деньги списываются один раз.
2. Через 25 секунд на склад поступает 10 единиц.
3. При недостатке денег заказ отклоняется.
4. Пятый одновременный ящик отклоняется.
5. При закрытии дня оплаченные поставки не исчезают.
6. Аренда 50 ₽ списывается ровно один раз.
7. Закрыть игру на экране итогов, запустить снова и нажать «Продолжить»: должна открыться следующая смена с сохранённой кассой и складом.

## Сохранения

1. Создать сохранение v2 и проверить кириллицу, копейки, склад и `journalIds`.
2. Подложить тестовый JSON v1: он должен загрузиться и мигрировать в память до v2.
3. Повредить основной JSON, не трогая `.bak`: игра должна прочитать backup.
4. Проверить fallback записи на целевой платформе.
5. Проверить лимиты и отбрасывание партий с пустым ID, отрицательным количеством, `NaN` и `Infinity`.
6. Новая история при существующем сохранении требует подтверждения.

## Настройки и ресурсы

1. Изменить чувствительность, head-bob и громкость; перезапустить игру и проверить сохранение значений.
2. Несколько раз войти и выйти из PlayMode с отключённым Domain Reload; проверить отсутствие накопления подписок и заметного роста runtime-ресурсов.
3. Переключать радио: старые синтезированные клипы должны освобождаться.
4. Проверить паузу: время, очередь, kinematic-машина и звук останавливаются.

## Автоматические тесты

В Unity:

```text
Window → General → Test Runner → EditMode → Run All
```

Из командной строки, заменив `UNITY_EDITOR` на путь установленного лицензированного редактора:

```bash
"$UNITY_EDITOR" -batchmode -projectPath . -executeMethod WarmBread.Editor.ProjectSetup.Prepare -quit -logFile prepare.log
"$UNITY_EDITOR" -batchmode -projectPath . -runTests -testPlatform EditMode -testResults test-results.xml -logFile tests.log
"$UNITY_EDITOR" -batchmode -projectPath . -executeMethod WarmBread.Editor.ProjectSetup.BuildWindows -quit -logFile build.log
```

GitHub Actions выполняет бесплатную статическую проверку. Unity-тесты в CI не запускаются, пока отдельно не настроены Unity license secret и runner.

## Визуальная приёмка

- 16:9 720p и 1080p, затем 16:10 и 21:9.
- Проверить края UI и длинные русские строки.
- Осмотреть сцену в 06:00, 12:00 и 19:30.
- NPC читаются на фоне окна и улицы.
- Дождь не идёт внутри ларька.
- Нет заметного z-fighting, розовых материалов и чрезмерного bloom.
- Нет мерцания теней и луж.
- UI не принимает клики через уже уничтоженные панели.

FPS, CPU, GPU, VRAM и GC нужно измерять в Development Build, а не оценивать по исходникам. Для приёмки сделать реальные скриншоты и короткую запись прохождения из Unity.
