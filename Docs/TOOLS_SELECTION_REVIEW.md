# Разбор предложенных библиотек — что реально ставить

## Решение для «Тёплого хлеба»

Не устанавливать весь список одновременно. Реализм дают прежде всего свет, материалы, звук, анимации, композиция сцены и оптимизация. Большой набор ассетов не заменяет эти системы и может ухудшить стабильность проекта.

## Добавить в основной стек

### Cinemachine
**Да.** Нужна для FPS-камеры, мягкого head-bob, событийной тряски и переходов. Использовать умеренно: камера не должна постоянно дёргаться.

### Addressables
**Да, после появления контента.** Полезна для повторно используемых NPC, декораций, аудио и вариантов погоды. Не нужна на самом первом блок-ауте.

### Unity Localization
**Да.** Проект русскоязычный, но ключи локализации лучше заложить сразу. Сохранять ключи, а не готовые фразы.

### ProBuilder
**Да, временно для blockout.** Хорош для быстрого прототипа ларька и улицы. Финальную геометрию нужно заменить оптимизированными prefab-модулями.

### Unity Recorder
**Да, только Editor.** Нужна для трейлера, тестовых видео и проверки камеры. Не добавлять в runtime-логику.

### Graphy или собственный debug HUD
**Один вариант.** Для контроля FPS и памяти достаточно Graphy либо уже запланированного внутреннего debug HUD. Не ставить оба без причины.

## Не добавлять сейчас

### Odin Inspector
Полезный, но платный и не обязательный. Сначала сделать валидаторы на стандартном инспекторе. Добавлять только если количество ScriptableObject-конфигураций станет трудно поддерживать.

### DOTween Pro / PrimeTween
Для UI-анимаций можно использовать обычные Animator/Coroutine. Если понадобится tween-библиотека, выбрать одну: предпочтительно DOTween, но не одновременно DOTween и PrimeTween.

### UniTask / R3
Не обязательны. Coroutine и C# events достаточно для текущего масштаба. R3 может конфликтовать с уже запланированным EventBus. Добавлять только при реальной потребности в сложных потоках.

### Zenject / Extenject
Не добавлять на раннем этапе. Сначала использовать простой composition root и интерфейсы. DI-фреймворк вводить после стабилизации систем, иначе он усложнит отладку сцены.

### Hot Reload
Опционально и только для Editor. Не является runtime-зависимостью и не должен попадать в релизный стек.

### Behavior Designer, NodeCanvas, Flow Core, NEXUS Core
Выбрать максимум один инструмент, но сейчас не ставить ни один. В проекте уже предусмотрена State Machine. Для очереди и конфликтов она прозрачнее и легче. Behavior Tree имеет смысл позже, если появятся десятки независимых целей NPC.

### Dialogue System for Unity / Ink
Выбрать один путь. Для текущего проекта достаточно собственной DialogueService с ключами и условиями. Ink стоит добавить только при большом ветвящемся сюжете.

### Inventory Engine / Ultimate Inventory System
Не ставить. Инвентарь ларька простой и уже покрывается собственными моделями склада, корзины и товаров. Внешний inventory framework создаст лишний слой.

### Easy Save, Vault, Crystal Save, Smart Save
Не ставить несколько систем сохранения. Текущий SaveSystem уже предусматривает JSON, backup, валидацию и миграции. Easy Save можно рассматривать позже, если появятся облачные слоты, но не смешивать с текущим форматом.

### Enviro 3, UniStorm, COZY
Выбрать максимум одну погодную систему. Для 3D-ларька лучше сначала сделать собственный лёгкий WeatherService на URP Volume, Particle System и смене освещения. Тяжёлые погодные ассеты не нужны для первой вертикальной версии.

### Beautify 3 / Snapshot Shaders
Не добавлять на старте. URP Volume уже покрывает цветокоррекцию, bloom, vignette и film grain. Сначала добиться хороших материалов и света, а не накладывать фильтры.

### Bakery GPU Lightmapper
Опционально. Сначала проверить встроенный Progressive Lightmapper. Bakery стоит покупать только после теста большой сцены и подтверждения, что время запекания реально мешает работе.

### Master Audio / Audio Toolkit / Sounds Good
Выбрать максимум один или оставить собственный AudioManager + AudioMixer. Для маленького проекта стандартный Unity AudioMixer достаточен.

### A* Pathfinding Project Pro
Не ставить пока. Unity AI Navigation уже установлен и подходит для очереди. A* добавлять только если профилирование докажет, что NavMesh не справляется.

### PCG Graph / Procedural World-Level Generator
Не нужно для одной улицы и одного ларька. Ручная композиция даст более правдоподобную атмосферу начала 2000-х и лучший контроль деталей.

### Asset packs, 4K PBR и огромные библиотеки анимаций
Покупать только после выбора единого стиля. Не смешивать Synty, реалистичные модели и случайные low-poly наборы. Для каждой покупки проверить URP-совместимость, лицензию, texel density и размер файлов.

## Что действительно добавить для реализма

1. **Light Probe Group + Reflection Probe** для NPC, витрины и стекла.
2. **URP Volume Profile** с отдельными профилями для утра, дождя и вечера.
3. **LODGroup, Occlusion Culling и GPU Instancing** для домов, машин и деревьев.
4. **AudioMixer** с Master/Music/Ambience/SFX/Radio/Voice.
5. **Footstep/Surface system**: разные шаги по асфальту, бетону, плитке и металлу.
6. **Material response system**: грязь, мокрый асфальт, запотевшее стекло, потёртая краска.
7. **Animation Rigging** только для рук, выкладки товара и передачи денег.
8. **Object Pooling** для NPC, дождя, мусора, реплик и эффектов.
9. **Performance budget** с измерением FPS, CPU, GPU, VRAM и GC.
10. **Content Validator** для ScriptableObject ID, prefab-ссылок, аудио-лицензий и missing references.

## Правило установки

Добавлять новый пакет только после короткого теста:

1. чистая ветка проекта;
2. установка одного пакета;
3. открытие всех тестовых сцен;
4. компиляция без ошибок;
5. запуск EditMode/PlayMode tests;
6. проверка размера билда и времени кадра;
7. фиксация версии и лицензии в документации.

Не добавлять в репозиторий случайные DLL, скомпилированные Library/Temp-файлы или ассеты без подтверждённой лицензии.
