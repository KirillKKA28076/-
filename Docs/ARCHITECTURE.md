# Архитектура 0.2

## Входная точка

`Bakery_Street.unity` → `GameBootstrap.Start`:

1. подготовка runtime-шрифта;
2. создание и инициализация `GameSession`;
3. создание очереди покупателей;
4. создание атмосферы и UI;
5. построение мира и NavMesh;
6. создание FPS-контроллера;
7. подключение аудио и интерфейса.

Сцена хранит стабильную ссылку на единственный runtime-класс `WarmBread.GameBootstrap`. Unity `.meta`-файлы закоммичены. `ProjectSetup` идемпотентно создаёт URP-ресурсы, TMP Essentials, редактируемые `ProductData`/`CustomerData` и Build Settings.

Ветка `main` является единственным актуальным источником проекта. Старая ветка `warm-bread-playable-v01` сохранена только как исторический checkpoint.

## Источник истины

Версия 0.2 использует одну игровую модель — `GameSession`.

Она владеет:

- временем и номером смены;
- кассой и статистикой дня;
- складом, пакетом и поставками;
- репутацией;
- дневником историй;
- checkpoint-сохранениями.

Параллельные экспериментальные реализации `WorldClock`, `EconomyLedger`, `DeliveryService`, второго EventBus и второго bootstrap не включены в runtime. Это предотвращает расхождение денег, времени и сохранений.

## Модули

| Модуль | Ответственность |
|---|---|
| `ProductData` / `CustomerData` | Редактируемые определения ассортимента и покупателей, стабильные ID |
| `Inventory` / `StockBatch` | FIFO, партии, время приготовления и резервирование в пакет |
| `Order` / `Money` | Неизменяемое снаружи содержимое заказа, цена и целые копейки |
| `GameSession` | Смена, касса, поставки, репутация, журнал и checkpoint |
| `QueueManager` / `CustomerAI` | Очередь, NavMesh, состояния, терпение, уход и конфликт |
| `PlayerController` / `InteractionTarget` | New Input System, движение, raycast и действия |
| `WorldBuilder` / `WorldArt` | Детерминированное окружение и управляемые runtime-ресурсы |
| `Atmosphere` | Дневной свет, дождь, синтезированная музыка и SFX |
| `GameUI` | Canvas/TMP: меню, HUD, блокнот, касса, итоги и пауза |
| `SaveSystem` / `SaveData` | Версионированный JSON, `.tmp`, `.bak`, валидация и миграция v1 → v2 |
| `ProjectSetup` | TMP Essentials, URP, каталог, Build Settings и Windows-сборка |
| `ContentValidator` | Сцена, шейдеры, ID, обязательные поля и missing scripts |

## Каталог и ID

Каталог загружается из `Resources/Products`, удаляет дубликаты ID и дополняется отсутствующими базовыми товарами. Базовый порядок стабилен, а неизвестные пользовательские товары сортируются после стандартных.

Горячие клавиши используют ID (`bread_white`, `pirozhok_meat`, `lemonade`, `gum`), а не индексы массива.

Покупатели имеют стабильный `CustomerData.Id`. Поздний посетитель определяется полем `LateVisitor`, а не положением в массиве. Текст истории больше не используется как технический идентификатор.

## Транзакция продажи

1. Заказ генерируется из фактически доступного ассортимента; ребёнок не получает табачные товары.
2. `Inventory.Take` резервирует единицу из самой старой партии и сохраняет исходный `bakedAt`.
3. Выдача разрешена только при полном совпадении состава и количества.
4. Стадия `Paying` блокирует изменение пакета и приостанавливает таймер терпения текущего покупателя.
5. Неверная сдача уменьшает репутацию, но не переводит деньги и не закрывает транзакцию.
6. Верная сдача единожды добавляет стоимость заказа, записывает историю и выводит NPC из очереди.
7. При уходе или закрытии смены пакет возвращается с исходным сроком годности.

## Сохранения

Формат `SaveData.CurrentVersion = 2` хранит:

- номер следующей доступной смены;
- кассу;
- репутацию;
- партии склада;
- отображаемые тексты дневника;
- стабильные ID уже открытых историй.

Запись выполняется во временный файл, затем атомарно заменяет основной файл и сохраняет `.bak`. На платформах без `File.Replace` используется безопасный fallback через копирование backup и перемещение временного файла.

Формат v1 мигрирует в v2 при загрузке. Некорректные диапазоны, чрезмерные коллекции, пустые ID и повреждённые партии отбрасываются. Если основной JSON повреждён, загрузка пробует `.bak`.

При закрытии смены сразу сохраняется checkpoint следующего утра. Поэтому выход на экране итогов не теряет деньги и склад и не приводит к повторному списанию аренды. Очередь, пакет и незаконченная транзакция внутри смены пока не сохраняются.

## Runtime-ресурсы

`WorldArt` кэширует материалы по полному набору параметров, а не только по имени. Динамические материалы, текстуры и TMP Font Asset уничтожаются при сбросе подсистемы.

`Atmosphere` освобождает синтезированные `AudioClip` и материал дождя. Громкость, чувствительность мыши и head-bob сохраняются через `PlayerPrefs`.

Движущаяся машина использует kinematic `Rigidbody` и перемещается в `FixedUpdate`.

## Проверка

- `Tools/validate_project.py` проверяет структуру, C#-грамматику, JSON, GUID, сцену, обязательные пакеты и глифы шрифта.
- GitHub Actions запускает эту проверку на `main`, ремонтных ветках и pull request.
- `ContentValidator` выполняет проверки контента внутри Unity.
- EditMode-тесты покрывают деньги, FIFO, срок годности, состав заказа, сериализацию и стабильные ID.

Статическая проверка не компилирует Unity API и не заменяет EditMode, PlayMode, профилирование и реальную Windows-сборку.
