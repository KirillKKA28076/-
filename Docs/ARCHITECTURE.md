# Архитектура «Тёплого хлеба» 0.3

## Общая схема

```text
Bakery_Street.unity
        ↓
GameBootstrap
        ├── WorldArt.PrepareFont
        ├── GameSession.Initialize
        ├── QueueManager.Initialize
        ├── WorldBuilder.Build
        │     ├── Environment
        │     ├── Kiosk
        │     ├── ModelFactory
        │     ├── StockDisplay
        │     ├── Lighting / Volume / ReflectionProbe
        │     └── runtime NavMeshSurface
        ├── PlayerController.Initialize
        ├── Atmosphere.Initialize
        └── GameUI.Initialize
```

Сцена содержит только стабильную ссылку на один `GameBootstrap`. Мир создаётся детерминированно во время запуска. В проекте нет второго bootstrap или параллельной экономики.

## Единый источник игрового состояния

`GameSession` хранит и изменяет:

- день и игровое время;
- кассу и расходы;
- продажи и выручку;
- репутацию;
- текущую цель;
- общий прогресс кампании;
- склад и пакет;
- доставки;
- журнал историй;
- состояние оплаты;
- закрытие смены и финал.

UI, очередь, атмосфера и мир читают состояние через `GameSession`, но не создают собственные копии денег, времени или поставок.

## Семидневная кампания

`CampaignRules` возвращает неизменяемый `DayPlan`.

Каждый план определяет:

- название и описание события;
- цель по продажам;
- цель по выручке;
- аренду;
- премию;
- множитель интервала покупателей;
- время доставки;
- погоду;
- товары повышенного спроса.

После седьмого дня `CampaignRules.EndingId` выбирает финал по:

- репутации;
- кассе;
- общему числу продаж.

Далее `CampaignRules.Get(day > 7)` генерирует свободный режим с постепенно меняющимися параметрами.

## Транзакция продажи

1. `QueueManager` выбирает покупателя и строит заказ только из доступного товара.
2. Для ребёнка исключаются ID с префиксом `sig_`.
3. `DayPlan.DemandWeight` повышает вероятность тематических товаров дня.
4. `Inventory.Take` резервирует единицу самой старой партии.
5. `Order.Matches` требует полного совпадения ID и количества.
6. Стадия `Paying` блокирует изменение пакета и останавливает терпение покупателя.
7. Неверная сдача снижает репутацию, но не переводит деньги.
8. Верная сдача пополняет кассу ровно один раз, записывает историю и удаляет NPC из очереди.
9. При уходе покупателя пакет возвращается с исходным `bakedAt`.

## Склад

`Inventory` хранит список `StockBatch`:

```text
productId
quantity
bakedAt
```

Правила:

- FIFO по `bakedAt`;
- количество не может быть отрицательным;
- пустые ID и нечисловое время отвергаются;
- возврат не обновляет срок годности;
- просрочка удаляется по данным `ProductData`;
- `StockDisplay` подписывается на `EventBus.Changed` и синхронизирует число видимых моделей на полке с реальным остатком.

## Покупатели

`CustomerAI` использует состояния:

```text
Arriving → Waiting → Ordering → Paying → Leaving
```

`QueueManager` отвечает за:

- создание NPC;
- позиции очереди;
- дневной seed случайности;
- плотность потока;
- тематический спрос;
- конфликт;
- завершение и уход.

`CustomerAI` отвечает за:

- NavMeshAgent;
- терпение;
- переходы локального состояния;
- анимацию процедурного рига;
- запрос ухода.

Бизнес-логика денег и товара остаётся в `GameSession`.

## Процедурная 3D-система

### `ProceduralMeshFactory`

Создаёт и нормализует runtime-меши:

- lathe-поверхности;
- батоны и пирожки;
- торы;
- фасонные коробки;
- экструдированные профили.

Каждый меш получает вершины, треугольники, UV, нормали, bounds и tangents, если они поддерживаются.

### `WorldArt`

Отвечает за:

- кэш материалов по полному набору параметров;
- URP Lit и fallback Standard;
- прозрачные и металлические материалы;
- процедурную грязь;
- кэш общих мешей;
- создание объектов и коллайдеров;
- TMP-надписи;
- runtime-свет;
- очистку сгенерированных нативных ресурсов.

### `ModelFactory`

Собирает высокоуровневые модели:

- покупателей с ригом;
- автомобили;
- скамейки;
- деревья;
- фонари;
- кассу;
- радио;
- чайник;
- телефон;
- кота;
- ящики и кружки.

`WorldBuilder` отвечает только за композицию сцены и размещение моделей.

## Статическая и динамическая геометрия

`WorldBuilder` разделяет:

- `street` — статическая геометрия двора и NavMesh;
- `interior` — ларёк и интерактивные объекты;
- `dynamicRoot` — транспорт и другие движущиеся объекты.

Перед `NavMeshSurface.BuildNavMesh` статическая уличная иерархия помечается через `WorldArt.MarkStatic`. Движущийся автомобиль находится вне собираемой иерархии и использует kinematic Rigidbody.

## Атмосфера

`Atmosphere` применяет погоду из текущего `DayPlan`:

- emission осадков;
- скорость частиц;
- fog density и цвет;
- интенсивность солнца;
- WindZone;
- громкость фонового шума.

Освещение продолжает плавно меняться по игровому времени. Радио, дождь и звон монет создаются синтезом, а созданные `AudioClip` уничтожаются при завершении.

## UI

`GameUI` содержит:

- главное меню;
- HUD;
- карточку заказа;
- пакет;
- кассу;
- блокнот;
- экран поставщика;
- журнал;
- страницу кампании;
- паузу;
- дневной отчёт;
- финальный экран.

HUD обновляется с ограниченной частотой, а тяжёлые панели перестраиваются только при изменении модального состояния.

## Сохранения v3

`SaveData` хранит:

- день;
- кассу;
- репутацию;
- склад;
- журнал и стабильные ID историй;
- total sales / revenue;
- выполненные цели;
- состояние кампании;
- ending ID.

`SaveSystem`:

1. сериализует во временный файл;
2. заменяет основной файл;
3. сохраняет `.bak`;
4. использует fallback для платформ без `File.Replace`;
5. валидирует диапазоны и размер коллекций;
6. мигрирует v1/v2 в v3;
7. при чтении сначала пробует основной файл, затем backup.

Checkpoint соответствует началу смены. Очередь и незаконченная кассовая операция посреди дня не сериализуются.

## События

Минимальный `EventBus` используется только для представления:

- `Changed` — обновление HUD и витрины;
- `Message` — игровая реплика;
- `Chime` — короткий звуковой сигнал.

События сбрасываются через `SubsystemRegistration`, поэтому отключение Domain Reload не накапливает старые подписки.

## Проверки

### EditMode

Проверяются деньги, FIFO, просрочка, точный заказ, read-only состав заказа, сериализация v3, ID, семь планов, три финала и геометрия процедурных мешей.

### Unity Content Validator

Проверяются сцена, Build Settings, обязательные скрипты, URP-шейдеры, товары, покупатели, планы кампании, финалы, генерация мешей и missing scripts.

### GitHub Actions

`Tools/validate_project.py` проверяет C#-грамматику, JSON, GUID, `.meta`, шрифт, структуру кампании, обязательный model API и допустимые значения `UnityEngine.PrimitiveType`.

## Осознанные ограничения

- runtime NavMesh и большое число объектов требуют проверки времени старта;
- модели не имеют UV-атласа production-уровня;
- нет скелетной анимации;
- UI создаётся кодом, поэтому визуальная редактура сложнее;
- нет сохранения внутри смены;
- финальная производительность определяется только реальным Unity-билдом.
