# Тёплый хлеб

**Маленький ларёк. Большой двор. Сентябрь, 2002.**

Атмосферный 3D-симулятор продавца хлебного ларька от первого лица. Игрок открывает точку в дождливом постсоветском дворе, следит за свежестью товара, собирает точные заказы, вручную считает сдачу, успокаивает очередь и постепенно узнаёт постоянных покупателей.

## Статус версии

Версия **0.3 — законченная исходная семидневная кампания** для Unity **2022.3.62f1 LTS / URP**.

В проекте есть:

- начало истории и главное меню;
- семь полноценных смен с разными условиями;
- ежедневные цели, аренда, премии и изменяющийся спрос;
- три финала кампании;
- свободный режим после завершения недели;
- сохранение прогресса между сменами;
- процедурно созданный детализированный 3D-мир без внешних модельных пакетов;
- редакторский валидатор, EditMode-тесты и GitHub Actions.

Это законченный игровой прототип с финалом, а не готовый коммерческий релиз. Unity Editor отсутствовал в среде, где подготовлены коммиты, поэтому перед распространением необходимо выполнить локальную компиляцию, PlayMode-проверку и Windows-сборку. Статическая проверка GitHub не заменяет запуск Unity.

## Быстрый запуск

```bash
git clone https://github.com/KirillKKA28076/-.git WarmBread
cd WarmBread
```

1. Откройте папку проекта через Unity Hub: **Add → Add project from disk**.
2. Используйте **Unity 2022.3.62f1**. Для сборки установите Windows Build Support.
3. Дождитесь импорта официальных пакетов.
4. Запустите **Тёплый хлеб → 1. Подготовить проект**.
5. Запустите **Тёплый хлеб → 4. Проверить проект**.
6. Откройте сцену через **Тёплый хлеб → 2. Открыть игровую сцену**.
7. Нажмите **Play → Начать семидневную историю**.

До Play сцена намеренно содержит только объект `Warm Bread Bootstrap`. Район, ларёк, освещение, витрина, NPC и интерфейс создаются детерминированно при запуске.

## Основной игровой цикл

1. Утром проверить запас и цель смены.
2. Дождаться покупателя и прочитать заказ.
3. Взять с витрины точный состав заказа.
4. Передать пакет и открыть кассу.
5. Вручную набрать правильную сдачу из купюр и монет.
6. Следить за терпением очереди, конфликтами и сроком годности.
7. Заказывать ящики у поставщика, пока хватает денег и места в машине.
8. Закрыть смену, оплатить аренду и получить премию за выполненную цель.
9. После седьмого дня получить один из трёх финалов.

## Семидневная кампания

| День | Событие | Особенность |
|---:|---|---|
| 1 | Первое утро | знакомство с районом и базовым спросом |
| 2 | Холодный дождь | чаще покупают горячую выпечку, очередь нетерпеливее |
| 3 | После школы | растёт спрос на лимонад и жвачку |
| 4 | День получки | плотный поток и крупные заказы |
| 5 | Туманное утро | медленные поставки и плохая видимость |
| 6 | Ветер с рынка | нестабильный спрос и ускоренный поток |
| 7 | Воскресенье двора | финальная смена и определение судьбы ларька |

Каждый день задаёт:

- цель по числу покупателей;
- цель по выручке;
- размер аренды;
- премию;
- скорость появления покупателей;
- время доставки;
- погоду;
- товары повышенного спроса.

Финал зависит от доверия района, состояния кассы и общего числа обслуженных людей. После финала кампания переходит в бесконечный свободный режим.

## 3D-модели и окружение

Модели создаются кодом во время запуска, но больше не состоят только из базовых кубов.

### Покупатели

- отдельные головы, лица, глаза, носы, рты и уши;
- несколько вариантов волос, шапок и кепок;
- пальто с планками и пуговицами;
- шарфы, брюки, обувь и кисти рук;
- сумки и сложенные зонты;
- разные пропорции ребёнка и взрослых;
- процедурная походка, движение рук, дыхание, взгляд и жесты оплаты.

### Товары

- батон и бородинский хлеб на собственных сглаженных мешах;
- надрезы и мякиш;
- пирожки с защипами;
- булочка-завиток с маком;
- бутылки на lathe-меше с крышками и этикетками;
- пачки сигарет с фольгой и печатью;
- упаковка жвачки;
- витрина визуально пустеет и наполняется вместе с реальным складом.

### Транспорт и двор

- детализированные седаны: кузов, капот, багажник, кабина, стёкла, ручки, зеркала, фары, бамперы и колёса;
- движущийся автомобиль на kinematic Rigidbody;
- панельные дома с окнами, рамами, шторами, балконами, подъездами, трубами и антеннами;
- остановка со стеклом, лавкой и объявлениями;
- скамейки, урны, фонари, провода, велосипед, люк и ливневые решётки;
- тополя со стволами, ветками и вариантами осенней кроны;
- мокрый асфальт, лужи, листья и дорожная разметка.

### Ларёк

- фасад, вывеска, полосатый козырёк и окно выдачи;
- подробная касса «Электроника»;
- радиоприёмник со шкалой, динамиком и антенной;
- эмалированный чайник и кружка;
- дисковый телефон;
- деревянные ящики, блокнот, карандаш, монеты;
- кот Плюш с глазами, ушами, хвостом и усами;
- локальный тёплый свет и Reflection Probe.

## Погода и атмосфера

Система погоды связана с кампанией:

- морось;
- сильный дождь;
- туман;
- ясное холодное утро;
- сильный ветер.

Меняются интенсивность осадков, туман, оттенок неба, сила света, ветер и громкость фоновой атмосферы. В течение смены солнце, освещение и цвет тумана плавно меняются от утра к вечеру.

Радио, дождь и звон монет синтезируются кодом. В проекте нет нелицензированных записей реальных радиостанций.

## Экономика и товары

- все денежные значения хранятся целыми копейками;
- FIFO-партии товара;
- срок годности не обновляется при возврате пакета;
- просроченный товар списывается;
- поставки оплачиваются заранее;
- одновременно разрешено до четырёх доставок;
- неверная сдача не завершает продажу и снижает доверие;
- ребёнок не заказывает сигареты;
- ежедневная цель даёт премию и дополнительное доверие;
- закрытие смены списывает аренду ровно один раз.

## Сохранения

Формат сохранения: **v3**.

Хранятся:

- день;
- касса;
- доверие;
- партии товара;
- открытые истории;
- общее число продаж и выручка;
- число выполненных целей;
- состояние кампании и полученный финал.

Файл:

```text
warm-bread-v1.json
```

Имя сохранено ради совместимости с ранними версиями. На Windows файл обычно находится здесь:

```text
%USERPROFILE%/AppData/LocalLow/WarmBread/Тёплый хлеб/
```

Запись выполняется через временный файл и резервную копию `.bak`. Поддерживается миграция старых сохранений v1/v2 в v3.

Сохраняется начало смены. Незаконченная очередь, пакет и кассовая операция внутри текущего дня после перезапуска не восстанавливаются.

## Проверки

### В Unity

```text
Тёплый хлеб → 4. Проверить проект
```

Валидатор проверяет:

- сцену и Build Settings;
- кириллический шрифт;
- обязательные URP-шейдеры;
- каталог товаров и покупателей;
- уникальность ID;
- экономические значения;
- семь планов кампании и три финала;
- формат сохранений;
- создание процедурных мешей;
- отсутствующие MonoBehaviour.

### EditMode-тесты

```text
Window → General → Test Runner → EditMode → Run All
```

Тестируются деньги, сдача, партии, просрочка, заказы, сериализация v3, ID, планы кампании, финалы и геометрия процедурных мешей.

### Статическая проверка

```bash
python -m pip install -r Tools/requirements-validator.txt
python Tools/validate_project.py
```

GitHub Actions запускает эту проверку при изменениях `main`, `feature/**`, `repair/**` и в pull request.

### Windows x64

```text
Тёплый хлеб → 3. Собрать Windows x64
```

Результат:

```text
Builds/Windows/WarmBread.exe
```

Сборка использует `BuildOptions.StrictMode` и предварительно запускает подготовку и проверку контента.

## Честные границы версии 0.3

- модели детальные процедурные, но не заменяют вручную сделанные и UV-развёрнутые production-меши;
- нет motion-capture и скелетной анимации;
- нет озвучки диалогов;
- нет сохранения посреди смены;
- нет физического денежного ящика с конечным запасом номиналов;
- GI и occlusion culling не запечены;
- производительность ещё должна быть измерена в реальном Windows-билде;
- компиляция Unity и PlayMode в текущей среде не выполнялись.

Архитектура описана в `Docs/ARCHITECTURE.md`, полный план проверки — в `Docs/QA.md`, дальнейший production-polish — в `Docs/ROADMAP.md`.
