# Тёплый хлеб

**Маленький ларёк. Большой двор. Сентябрь, 2002.**

Атмосферный 3D-симулятор от первого лица: ручная сдача, свежая выпечка, очередь и маленькие истории соседей. Снаружи — холодный дождливый двор с панельными домами, внутри — выцветшая бирюза, радио и тёплый свет лампы.

## Статус версии

Версия **0.2 — единый исходный вертикальный срез** для Unity 2022.3 LTS.

В основную ветку сведены сцена, UI, процедурный мир, игровая логика, сохранения, тесты и редакторская подготовка проекта. Устранены разошедшиеся реализации bootstrap, времени, денег и поставок. Основная игровая модель теперь одна — `GameSession`.

Это исходники прототипа, а не готовый коммерческий релиз. Unity Editor отсутствует в среде, где подготовлены эти коммиты, поэтому локальная компиляция Unity, PlayMode и Windows-сборка всё ещё должны быть выполнены на машине с Unity. Статическая проверка репозитория не заменяет запуск игры.

## Открыть и запустить

1. Клонируйте основную ветку:

   ```bash
   git clone https://github.com/KirillKKA28076/-.git WarmBread
   cd WarmBread
   ```

2. В Unity Hub выберите **Add → Add project from disk** и укажите папку с `Assets`, `Packages` и `ProjectSettings`.
3. Откройте проект в **Unity 2022.3.62f1**. Для Windows-сборки установите Windows Build Support.
4. Дождитесь окончания импорта официальных Unity-пакетов.
5. Скрипт `ProjectSetup` подготовит URP, TMP Essential Resources, каталог товаров, покупателей и Build Settings. Подготовку также можно запустить вручную: **Тёплый хлеб → 1. Подготовить проект**.
6. Выполните **Тёплый хлеб → 4. Проверить проект**.
7. Откройте сцену через **Тёплый хлеб → 2. Открыть игровую сцену**, нажмите **Play**, затем **Открыть ларёк**.

До Play в сцене виден только `Warm Bread Bootstrap`: окружение детерминированно создаётся при запуске.

## Управление

| Управление | Действие |
|---|---|
| WASD / мышь | Ходьба / обзор |
| E / ЛКМ | Взаимодействие с объектом под прицелом |
| F | Выдать заказ / открыть кассу / успокоить конфликт |
| X | Вернуть собранный пакет на полки |
| 1 / 2 / 3 / 4 | Батон / мясной пирожок / лимонад / жвачка |
| ПКМ | Приблизить взгляд |
| Tab | Блокнот: ассортимент, поставки, истории |
| R | Две оригинальные радиопетли / выключить радио |
| Esc | Пауза, настройки, досрочное закрытие смены |

Горячие клавиши товаров привязаны к стабильным ID, а не к позиции товара в массиве.

## Что реализовано

- Процедурный район: панельные дома, балконы, тополя, скамейки, остановка, провода, машины, мокрый асфальт и лужи.
- Ларёк с полками, десятью базовыми товарами, кассой, телефоном, чайником, календарём и котом Плюшем.
- URP: мягкие тени, локальные источники света, туман, bloom, ACES, vignette, film grain, дождь и изменение дневного света.
- FPS-контроллер с коллизиями, руками и бумажным пакетом.
- Настройки чувствительности мыши, покачивания камеры и громкости сохраняются через `PlayerPrefs`.
- Покупатели с NavMesh, очередью, терпением, уходом и конфликтами.
- Во время экрана оплаты терпение текущего покупателя не уменьшается.
- Точный заказ и ручная сдача; неверная сдача не дублирует оплату.
- Деньги хранятся целыми копейками.
- Партии товара, FIFO, срок годности, возврат без обновления срока и списание просрочки.
- Поставки по десять единиц с ограничением числа заказов в пути.
- Итоги смены, репутация и дневник историй.
- Стабильные ID покупателей и отдельный признак позднего посетителя.
- Версионированные JSON-сохранения, временный файл, резервная копия и миграция формата v1 → v2.
- EditMode-тесты денег, партий, заказов, сохранений, каталога и ID покупателей.
- GitHub Actions выполняет статическую проверку структуры, C#-грамматики, JSON, GUID и кириллического шрифта.

## Сохранения

Файл `warm-bread-v1.json` хранится в `Application.persistentDataPath`. На Windows это обычно:

```text
%USERPROFILE%/AppData/LocalLow/WarmBread/Тёплый хлеб/
```

Старый файл сохраняется как `.bak`. Загрузка сначала проверяет основной файл, затем резервный.

Сохраняется начало смены. При закрытии дня дополнительно записывается безопасный checkpoint следующего утра: если игра закроется на экране итогов, заработанные деньги и остатки не потеряются, а аренда закрытого дня не спишется повторно.

Прогресс внутри незавершённой смены пока не восстанавливается: очередь, пакет и незаконченная операция после перезапуска начинаются заново от checkpoint смены.

## Сборка и тесты

### Проверка контента в Unity

```text
Тёплый хлеб → 4. Проверить проект
```

Валидатор проверяет:

- наличие сцены и шрифта;
- включение сцены в Build Settings;
- обязательные URP-шейдеры;
- уникальность и заполненность ID товаров и покупателей;
- цены, сроки годности и обязательные тексты;
- отсутствующие MonoBehaviour в открытой сцене.

### EditMode-тесты

```text
Window → General → Test Runner → EditMode → Run All
```

### Windows x64

```text
Тёплый хлеб → 3. Собрать Windows x64
```

Результат создаётся в:

```text
Builds/Windows/WarmBread.exe
```

Перед сборкой автоматически запускаются подготовка проекта и валидатор контента.

### Статическая проверка без Unity

```bash
python -m pip install tree-sitter tree-sitter-c-sharp fonttools
python Tools/validate_project.py
```

Этот скрипт не компилирует Unity API и не заменяет EditMode, PlayMode и визуальную проверку.

## Что обязательно проверить локально

Используйте [Docs/QA.md](Docs/QA.md). Минимум:

1. отсутствие красных ошибок Unity Console;
2. PlayMode сцены без розовых материалов;
3. подход первого покупателя и продвижение очереди;
4. правильный и неправильный заказ;
5. неверная и верная сдача;

7. поставка и списание денег;
8. просрочка выпечки;
9. закрытие дня, перезапуск и продолжение;
10. Windows Development Build на чистой машине.

## Ограничения вертикального среза

Пока нет:

- ригованных персонажей и полноценного IK;
- физического перекладывания каждого предмета;
- печи и мини-игры выпечки;
- озвученных ветвящихся диалогов;
- сохранения посреди смены;
- физической кассы с ограниченным количеством купюр;
- запечённого GI, LOD и финального occlusion culling;
- готовых коммерческих 3D-ассетов.

Мир намеренно собран из простой процедурной геометрии. Следующие этапы описаны в [ROADMAP](Docs/ROADMAP.md), архитектура — в [ARCHITECTURE](Docs/ARCHITECTURE.md), проверка — в [QA](Docs/QA.md).

Лицензия шрифта находится в `Docs/FONT-LICENSE.txt`. API-ключей, телеметрии, онлайн-сервисов и сторонних записей реальных радиостанций в проекте нет.
